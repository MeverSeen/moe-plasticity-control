# v7 连续多段学习验证记录

本轮新增 `experiments/v7_sequence_feedback/`，前六轮归档源码与数据保持不变。正式结果与小规模预检均保存，之后才更新根目录索引。

## 执行

```bash
python3 scripts/run_experiment.py v7 --pilot --out runs/v7-pilot
python3 scripts/run_experiment.py v7 --out runs/v7-main
python3 scripts/test_all.py
python3 scripts/analyze_sequence_diagnostics.py --run runs/v7-main
python3 scripts/analyze_sequence_diagnostics.py --run runs/v7-pilot
python3 scripts/verify_artifacts.py
```

Python 3.9.6、Torch 2.8.0、NumPy 2.0.2，CPU 单线程。正式运行约 381.1 秒，小规模预检约 23.8 秒；机器负载会影响复现用时。

正式历史为 64 train / 24 dev / 64 test，三个策略初始化，共 12 个学习控制器。所有新根历史编号与原有归档协议列出的历史无交集，训练/开发/最终测试之间也无交集。

## 机制检查

全部七轮共 **73 项检查通过**，v7 新增 12 项：

1. 连续手工 Adam 更新逐步匹配 PyTorch Adam，包含跨段偏置修正计数。
2. 跨段保留参数、Adam 矩、全局初始模型和 A 参考损失。
3. Progress 不读取刷新后的 A loss；仅修改当前 A 反馈不影响其输入。
4. 段间保持动作与段内重复相同动作得到完全一致的权重和工作量。
5. `m=0` 冻结保护组实际参数位移，同时保留矩更新。
6. 克隆分支不修改父状态、参数或未来批次索引。
7. 未来流按段与 replicate 配对，保留过去批次，跨动作对齐。
8. 修改全部独立测试标签不改变在线观测、更新或停止行为。
9. 失败段不会在最终序列达标评价中消失。
10. 保护组与记忆不随段刷新，内存和计算代理符合上限。
11. 屏蔽发生在标准化之后，输入维度与输出动作数正确。
12. 开发选择首先比较达标率，然后遗忘，再比较工作量。

此外逐条审计全部 **1,280** 条正式测试 rollout：三个段记录完整、累计步数连续、单段≤100/总计≤300、工作量不超预算、成功等价于全部段成功、数值有限。预检 96 条 rollout 也通过相同审计。

## 锁定与归档

每次运行先保存 `plan.json`，在生成最终测试历史前锁定源码、所选模型哈希与开发集选择的基线。运行前后源码一致，已核对全部锁定模型哈希。`model_core.py` 与 v6 的冻结版本逐字节一致。

正式结果 77 文件，预检 37 文件，均归档至 `experiments/v7_sequence_feedback/results/`。`manifest.sha256` 同时覆盖该版本源码、说明与结果；前六轮原有 668 个归档文件仍通过校验。根目录校验脚本已加入 v7。

`scripts/analyze_sequence_diagnostics.py` 是在主分析完成后加入的描述性复核，输出训练状态统计、按初始化的配对差以及两项主要比较的 97.5% 区间。它不改模型、策略选择、主要分析或测试历史；结果明确标注事后检查。复现入口在主分析后调用此脚本。

完整入口另运行一次 `--pilot --out runs/v7-reproduction-check`；原始分支、全部测试轨迹、基线选择、主统计与补充诊断等 7 个核心输出文件逐字节一致。

## 结论边界

段内旧知识反馈出现约 13.8% 的共同成功历史遗忘改善，但未完成达标率非劣效验证，多重比较敏感性区间跨零。段间反馈表现为更高达标率与更高遗忘的取舍。最终 B 保留不足、固定后续教师、固定几何 router、仅三个训练初始化、额外离线搜索开销均在报告中说明。
