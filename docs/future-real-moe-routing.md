# 待办：真实 MoE 中的当前路由反馈

记录于 2026-09-16。用户决定：当前最小实验暂不增加路由动态；到真实 MoE 阶段再处理。

2026-09-17 主线更新：下列要求在新的多层 MoE 环境中落实，已归档 v1–v7 不改动。共享逐 expert 控制、层级汇总与结构化探索见 [总体方案](mainline-plan.md) 和 [控制器设计](controller-design.md)；冻结 router 权重与固定样本分配需要分别命名。

## 当前实现的边界

当前几何 router 使用固定原始输入与固定矩阵，expert 更新不会改变固定监测样本的路由。重复测量同一组样本不会增加时间信息。更完整的 expert 级初始结构与重新测量动态结构是两个不同问题。

## 真实 MoE 阶段需要处理

1. 同时保留 B 开始前的历史路由、当前旧记忆路由和当前新任务路由；当前路由不能替代历史依赖关系。
2. 区分 Top-K 使用频率与实际门控权重，观察 expert 身份不变但权重改变的情况。
3. router 参数冻结不保证路由不变：上游隐藏表示的更新可能改变后续层路由。
4. 用固定旧记忆/新监测样本测量时间变化，将 minibatch 构成变化与路由迁移分开；记录观测额外成本。
5. 先在同一动作空间下消融当前路由的独立信息价值，再独立检验动态保护组或 expert 级更新分配。
6. 当前单个倍率只能调节固定保护组。若风险迁到组外，需要动作映射能够重新分配保护；单纯增加输入不足以实现该能力。
7. 路由漂移作为候选状态，不能直接等同于重要性或实际遗忘；router/上游变化造成的旧任务退化也未必能靠冻结 experts 解决。
8. 每个统计同时记录覆盖样本/token 数、缺失及距上次有效观测的时间。有限旧记忆没有激活某 expert，不代表该 expert 不承担旧能力；不能把缺失直接编码成安全的零值。
9. 多任务有限 memory 更新后，监测样本构成与任务覆盖也可能改变 usage；区分路由变化、样本替换和观测噪声，历史摘要的更新规则保持可追踪。

候选 expert 级输入：历史旧使用率、当前旧/新使用率、当前旧/新门控权重；采用共享编码器，避免依赖任意 expert 编号。需通过固定目标、预算及充分进度基线的消融验证。

参考：[Switch Transformer 路由定义](https://arxiv.org/html/2101.03961v3#S2.SS1)。
