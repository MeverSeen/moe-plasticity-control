# H=1 与实际参数位移奖励：CPU 玩具对照

正式结果见[结果解读](结果解读.md)，全部四组已完成；原始轨迹在`runs/v16/main/`，精简结果和校验清单在`archive/`。

用户提出直接把控制间隔改成1，并用参数变化量作为 reward。这里复用冻结的 v2 六 expert、固定 top-2 路由、870 参数 tanh 模型，在本机 CPU 跑 2×2 对照：H∈{1,5} × reward∈{遗忘,实际 Adam 位移}。不调整正在运行的 v15 语言模型实验。

参数变化量定义为所有可训练学生参数的逐步实际位移平方和：

`D_T = Σ_u ||θ_(u+1) − θ_u||²`。

它是路径代价，区别于相对学习起点的净位移 `||θ_T−θ_0||²`；两者均记录。不用原始梯度或 Adam 候选步代替实际执行位移。控制动作仍仅调节原有保护组的倍率，其余 experts 正常更新。

每个控制窗口的奖励为 `−ΔF/.01` 或 `−ΔD/s_D`，真正终点未达标再罚10；gamma=1，累计回报严格对应最终代价与失败惩罚。`s_D` 只由32个训练根上固定.5的正路径代价中位数确定，PPO前锁定。没有额外新 loss 塑形、reward裁剪或逐batch改变尺度。失败惩罚是训练代理，不是严格可行性保证；开发选模与报告首先看新任务是否达标。

保持原14维反馈输入、五档动作、64回放+64监测记忆、目标MSE≤.08、300次更新上限。两个H都逐步监测新旧loss，使用相同数据流和相同内层预算；H只改变重选动作的频率。因此这里没有把节省监测成本算给H=5。控制器调用及墙钟另报，不宣称总计算完全相同。

32 train /16 dev /48 fresh test roots，3个匹配策略种子。每模型32轮、每轮8条新on-policy轨迹，每轮4次全batch PPO更新，所有组优化步数相同；H=1的决策样本更多。GAE按实际learner步数使用 `.95**duration`，避免更换H时无意改变时间尺度。

复用v2的均匀actor初始化；greedy初始平局会选m=0，因此显式保留第0轮候选。开发在0/16/32轮按达标数、成功历史的监测遗忘、更新步数选模；同时报告最后一轮，不把选中初始化解释为学会冻结。五个常数和一条预先指定的简单反馈规则均保留。

固定动作下H=1和H=5必须得到逐位相同的模型、相同更新数及路径代价；奖励累计恒等式、实际位移和测试标签隔离均有针对性检查。原始每步loss/位移、决策、奖励、行为概率及PPO学习日志保留，可做后续离线诊断。

本轮是新合成种子上的小规模机制试验。路径平方代价可能奖励更小、更慢的更新；小权重变化不保证小功能变化。即使成功，也不能直接外推到原生MoE LoRA或认定H=1普遍更好。
