# v11：逐 expert RL 学习诊断

本轮继续项目的主目标：用当前学习状态驱动一个神经网络，控制不同专家的更新。先解释 v8 的 GRPO 为什么在部署时始终执行全量更新，再判断增加训练是否产生可用的学习控制。CPU 开发诊断；没有官方测试集或 GPU 实验。

**已完成：**四次 48 轮训练、20 个检查点、344 条开发轨迹均通过完整性审计。延长训练改变了策略；协调控制器的确定性部署与固定零专家位移完全一致，局部控制器种子间不一致。见[结果解读](结果解读.md)与[完整结果](results/development/analysis/研究诊断报告.md)。

## 固定协议

[`protocol.json`](protocol.json) 在运行前确定全部网格。直接复用冻结的 v8 环境、控制器与优化器语义：两层、每层 8 个专家，动作倍率为 0、0.5、1。两个控制器分别使用局部特征和额外的层内/全局特征汇聚。保持学习器、奖励、初始化、每组四条轨迹、每组一次策略更新及全部超参数不变。

- 训练根：原 v8 的 88100–88103；策略种子 881、882；局部和协调控制器各训练 48 轮。
- 预算检查点：0、3、6、24、48 轮，共享同一次训练的前缀。
- 冻结探针：训练根上固定全量更新参考轨迹的观测张量；只读概率，不影响训练或随机数。
- 开发根：88520–88523，仍使用 v8 的 25 个开发类别。每个检查点完整运行确定性部署和三次配对随机部署；另跑六个规则对照，总计 344 条开发轨迹。
- 配对：学习器按根与任务使用固定批次流；动作随机数按根、抽样编号、任务、步数固定，避免不同停止时间挪动下一任务的随机流。

`global_0` 表示专家参数位移为零；专家动量仍推进，前端与任务头继续训练。它不是冻结整个网络。使用同一新任务停止阈值，也不意味着最终 loss 严格相等或计算量相等。

## 检查内容与结论边界

分别记录原始奖励三分项、标准化优势、策略/熵梯度、裁剪前后梯度、实际参数变化、概率与确定性动作变化。标准化优势的平均损失接近零不代表梯度为零。v8 每组仅作一次在策略更新，因此重要性倍率接近 1、PPO 裁剪不生效是需要核对的算法行为。

新任务在线达标、独立开发样本的初学/最终达标、全历史正向 loss 增量、最终准确率及物理成本分别报告。随机抽样和策略种子先在根内平均，不能把它们当作更多独立根。所有失败保留；不给出确证性显著优势或非劣效结论。

运行必须通过种子 881 前六轮与旧归档奖励、决策次数及损失的回归比较。旧归档没有完整动作/logprob 日志，无法追溯比较这些字段；单元检查另验证仪器化更新与原算法权重一致。

## 复现

仓库根目录执行，已校验的 CIFAR-100 压缩包须在 `.cache/datasets/`：

```bash
python3 scripts/run_experiment.py v11 --out runs/v11-reproduction
python3 scripts/audit_v11_run.py --run runs/v11-reproduction
```

运行只加载官方 `train`，拒绝覆盖输出或在冻结实验目录内运行。开发数据已被反复用于研究设计；新根不是新类别，也不是独立确认实验。完整来源哈希、环境、所有检查点、探针、训练日志、完整评价矩阵和成本会分别保存。
