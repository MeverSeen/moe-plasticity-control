# 单倍率 MoE 反馈控制：首轮结果

2026-09-16

**实验已完成，本轮没有验证实时旧知识反馈优于固定倍率或进度控制。** 三个随机初始化下，progress PPO 和 feedback PPO 在开发集选择时均保留第 0 轮检查点；测试时全部执行保护组倍率 `m=0`。因此，主要比较的遗忘差为零来自实际策略相同，不是通过大样本证明两类最优控制器等价。

这是新的 6 专家非线性合成实验，不是前面用户报告的 4 专家线性 sanity check 的复现。代码复用了工作区已有 v1 的模型与数据生成器。旧 v1 文件和结果没有修改。

## 做了什么

在固定 870 个可训练参数、固定 top-2 路由的 6-expert MoE 中，先形成 1–3 个旧任务历史，再学习 B。每个 expert 是 10→12→1 的 tanh 网络。各任务输入域不同，标签来自同一个非线性教师，避免同一输入被人为赋予矛盾标签。

每个独立历史中，所有方法从同一个模型和同一组优化器初始状态出发，使用同一批次序列。根据旧样本和 B 初始监测输入的 routing usage，固定保护组：旧 usage ≥ 1/3 且新 usage ≥ 0.05。控制器每 5 步选择一次 `m ∈ {0, .25, .5, .75, 1}`，该组的 Adam 参数位移乘以 m，其他专家倍率为 1。固定回放系数为 0.1，没有额外保护正则项，没有 Fisher 特征。

旧样本预算为 64 个回放样本和 64 个监测样本。反馈控制器读取旧监测遗忘及其近期变化；progress 控制器的对应两个输入恒为 0。双方的架构、初始信息、B loss 与趋势、预算信息、上次动作和训练轮数都相同。监测数据不作为最终测试数据。

动作在每个 B 学习过程中反复选择；本轮测试是从标准预训练历史开始的一次 B 适应，不是控制器从第一任务起接管整个长期任务序列。router 是固定的合成路由，尚未验证 learned router 或语言模型。

## 配置如何选定

使用 12 个独立预跑历史校准目标：全更新在 MSE 0.06 下达标 9/12，在 0.08 和 0.10 下均为 12/12，因此选择较严格的 0.08。这个选择发生在正式训练与最终测试之前；保留了全部预跑记录。

训练使用 64 个历史，开发使用 24 个历史；最终测试为 80 个全新历史。两种 PPO 各训练 3 次，匹配随机种子 9171、9172、9173。每次 60 轮，每轮 12 个 episode，控制器有 1,734 个参数。其规模大于玩具学生模型，因此不能由此宣称大模型部署效率。

开发集搜索并锁定：

| 方法 | 候选数 | 开发集选定策略 |
|---|---:|---|
| 固定倍率 | 5 | m=0 |
| 两阶段进度调度 | 75 | 前后两阶段均为 m=0，退化为常数 |
| 简单反馈规则 | 48 | 监测遗忘超过 0.001 时 m=0.25，否则 m=1；不按剩余预算强制放开 |
| progress PPO | 每个训练种子 7 个检查点 | 三次均选第 0 轮 |
| feedback PPO | 每个训练种子 7 个检查点 | 三次均选第 0 轮 |

**第 0 轮 actor 的 logits 相同，确定性 argmax 按预设动作顺序选择 m=0。它是初始设定形成的固定策略，不是 RL 学出的冻结行为。** 训练后的检查点没有在开发集上胜过这个候选。没有根据测试结果改变动作顺序、训练目标或检查点。

两种 PPO 使用带失败惩罚的终点回报和势函数塑形。开发集选择首先最大化达标数，再最小化达标时的旧监测遗忘，最后比较工作量。所有配置、源码与选定权重哈希在生成最终测试世界之前锁定。

## 预算与评价定义

共同在线预算是一个明确的工作量代理：每个前向样本为 1 单位，前向加反向为 3 单位，控制器线性层 MAC 折算为学生前向单位；包括初始观测、routing 统计、每步新任务监测和每个控制窗口的旧任务监测。上限由 300 次模型更新和监测流程确定，同时保留 300 步硬上限。

这**不是精确硬件 FLOPs 或相同壁钟时间**。所有方法都执行同样的监测流程，progress 方法仅隐藏旧反馈，是信息消融设置。实际部署时不读取旧反馈的方法可能省去监测；本轮没有验证那种成本优势下反馈方法仍然有效。离线训练、调参和最终测试评估成本单列。

终点是 B 监测 MSE 首次 ≤ 0.08；不是不同模型数值严格相同的 loss。因此记录实际终点 loss，并补充 [0.076, 0.08] 内的更紧匹配分析。遗忘是每个旧任务的测试 MSE 相对 B 开始时的增加取正部，再对旧任务平均，单位为 MSE。最终测试集从不用于策略状态、训练奖励或开发集选择。

## 测试结果

| 方法 | 达标历史数 | 达标子集平均遗忘 MSE | 平均更新步数，含失败 | 平均在线工作单位 |
|---|---:|---:|---:|---:|
| 全更新 m=1 | 78/80 | 0.013456 | 42.85 | 14,662.5 |
| 开发集最佳固定 m=0 | 77/80 | 0.007180 | 49.13 | 16,748.9 |
| 开发集最佳进度调度 | 77/80 | 0.007180 | 49.13 | 16,748.9 |
| 简单反馈规则 | 78/80 | 0.011373 | 43.01 | 14,716.2 |
| progress PPO 选定策略，三个种子一致 | 77/80 | 0.007180 | 49.05 | 16,785.8 |
| feedback PPO 选定策略，三个种子一致 | 77/80 | 0.007180 | 49.05 | 16,785.8 |

各方法达标子集并不完全相同，不能直接把表中条件均值相减解释为整体效果。PPO 选定策略比固定 m=0 少约 0.075 平均更新步，是额外控制器推理消耗了部分工作预算，使失败历史略早停止；不是学习更快。所有共同达标的端点与固定 m=0 完全一致。

主要比较 feedback PPO − progress PPO：

- 80 个历史的达标率差为 0。
- 77 个共同达标历史的遗忘差为 0。
- 限制双方 loss 在 [0.076,0.08] 内，51 个配对端点差仍为 0。
- 排除零更新达标后，57 个共同达标历史差仍为 0。
- 所有实际执行的 PPO 选定策略动作均为 m=0，动作切换次数为 0。

对应 bootstrap 区间均为 [0,0]，只反映**实际选定策略产生相同轨迹**。不能解释成已经精确确定“反馈本身的价值为零”。三次训练也没有给出三个独立的动态部署策略。

相对全更新，在 77 个共同达标历史上，固定保护所对应的遗忘降低约 0.006253 MSE，配对历史 bootstrap 95% 区间为 [-0.008306,-0.004182]。但它少达标一个历史，平均工作量更高，因此这属于保持与学习效率之间的权衡，不能宣称严格支配全更新。此收益可由固定分组和固定冻结解释，没有学习型反馈增益。

## 诊断与限制

80 个测试历史中有 20 个在 B 开始前就满足目标，10 个的 B 路由流量不经过保护组，1 个几乎所有 B 流量都经过保护组。平均受保护 B gate mass 为 0.284。这些情况都保留在主结果中，同时提供排除零更新端点的分析。它们也表明该合成分布对动态调节的需求有限，不能代表更困难的长期学习场景。

在**开发集**上做了一个事后诊断：允许用已知终点结果从 5 个固定倍率中为每个历史选择最优动作。24 个历史中，18 个选择 m=0，5 个选择 m=0.25，1 个选择 m=0.5；平均旧监测遗忘从统一 m=0 的 0.007254 降至 0.006908，约改善 4.8%。这是使用未来结果的 oracle，不能部署；也不是所有动态策略可达收益的上界。它只说明本开发集上的静态动作差异空间不大。

本轮没有区分以下解释：场景中实际动态决策价值较小；PPO 训练不足；有限记忆反馈太噪；动作组过粗；有界且截断的训练回报不能充分区分策略。当前结果只支持“这套已实现训练与选择流程未得到更好的反馈控制器”。它不否定所有 RL 控制器，也不否定前面线性最小实验中的 routing interaction 机制。

## 检查、成本和交付

8 项检查通过：最终测试标签不可影响状态/更新/奖励；零倍率在存在动量时冻结保护组；分组及路由固定；progress 输入屏蔽当前旧反馈；工作预算计入策略与监测；旧记忆上限；奖励塑形望远镜一致性；专家置换不改变标量状态和对应更新。

本机 CPU 单线程：基线调参约 20.3 秒；六次 PPO 训练及其开发集验证合计约 50.7 秒；正式测试及历史构造约 26.7 秒。这些时间不包括全部预跑、公共训练/开发历史构造、制图和文件整理。相关逐阶段记录已保存。
